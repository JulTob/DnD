## ✅ Resolution
- **Decided by:** Julio, 2026-09-07 ("apply the changes").
- **What changed:** `06b93a5`'s 1,980-line source replaced the `marshal` shim
  verbatim, as a pure revert. Verified equivalent to the vault image before
  committing: all fifteen tables compare equal and the public surface matches.
  This also turned `Map_of_Materials` green — the shim had hidden `_CULTURES`
  because it re-exported only public names.
- **Practice/preference to remember:** a bytecode bootstrap is not a neutral
  placeholder. It silently drops `_`-private names, so a module importing a
  private from a shimmed module fails with an ImportError that reads like a
  missing symbol. Check that pattern first on any remaining bootstrap.
  Keep a restore commit *pure* — the Aasimar/Goliath correction was applied
  separately, so this one stays reviewable as a revert.

### One extra reason to prioritise it

The shim is not merely cosmetic. **It re-exports only public names**, skipping
anything beginning with `_`. That makes `Map_of_Materials` fail outright:

```
ImportError: cannot import name '_CULTURES' from AtlasInventarium.Map_of_Gear_Titles
```

The error reads like a missing symbol and is really a shim artefact. Any module
importing a private name from a shimmed module has the same latent break, so this
is worth checking across the other bootstraps too (cf. QST-0076-sweep).

Do **not** resolve it by copying `_CULTURES` into `Map_of_Materials`: two copies
of the species mapping is exactly the duplication the double mapping exists to
prevent.
