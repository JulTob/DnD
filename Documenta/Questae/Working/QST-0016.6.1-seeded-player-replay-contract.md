## 🔍 Diagnosis (what & where)

The public Player facade accepts a seed and the Shiny frontend exposes that
seed through a shareable URL.  Repeating the same valid request does not yet
replay the same sheet: `Isolated_Legacy_RNG` controls stdlib `random`, while
legacy Player production also uses the independent `app.random` singleton.

For `Human / Fighter / Soldier / level 1 / They / seed 42`, identity and
ability values stay stable but selected skills and fighting style vary across
strict repeated calls.  This is a user-visible breach of the share URL's
meaning, not object-representation noise.

## 🧾 Evidence

- `Tools_of_Legacy_RNG.Isolated_Legacy_RNG` seeds and restores only stdlib
  `random`.
- `app/random.py` owns a distinct module-level `random.Random` instance.
- Player generation reaches `app.random.choice` from
  `Grimoire_of_Skills.Skills.activate_proficiencies` and
  `Grimoire_of_Features.add_new_fighting_style`.
- Repeated normalized snapshots differ in proficient-skill ranks and the final
  fighting-style Feature; stable identity/stat/equipment fields rule out an
  incidental display difference.

## 🎯 Desired outcome

For each supported, valid explicit Player request:

1. Repeating the request produces an identical semantic Player-sheet
   projection, including selections, Features, skills, equipment, saves, and
   attack values.
2. The legacy-RNG quarantine restores both stdlib `random` and `app.random`
   state after success or failure, so a summon cannot perturb other work.
   Its temporary use of process-global state is serialized so concurrent
   summons cannot interleave their seed and restore phases.
3. A supplied seed is never silently changed to hide a generation error.
4. A deterministic test reports the first divergent field clearly.

The permanent destination remains Decree 0002: Character-owned Dice replace
all global entropy.  This slice makes the existing quarantine complete and
tested while QST-0016.2.3 / QST-0016.2.6 retire the legacy calls one bounded
surface at a time.

## 🧭 Notes for the Agora / implementer

- Do not make the test compare object addresses, raw reprs, or debug logs.
  Project semantic sheet values deliberately.
- Do not silence failures with retry-plus-seed-increment.  A strict request
  must either produce its requested Character or report the defect.
- Do not replace `app.random` globally in this slice.  The supported Player
  facade and its state boundary are the scope.
- The strict randomized sweep currently exposes a separate Fighter TagKit
  precondition error; record it as QST-0085 rather than weakening this test.
