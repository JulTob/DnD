## 🔍 Diagnosis (what & where)

QST-0018 removed `AtlasTOP/` on 2026-07-15. The 2026-08-29 restore to an old tree brought one file of it back, `AtlasTOP/archetypes.py` (59 lines), and the recovery commits tracked it. It is dead on arrival: it imports `._helpers`, which does not exist, there is no `__init__.py`, and nothing in the repository imports `AtlasTOP`.

Two documents still point at it as if it were live:

- `Canon/TagKit-Doctrine.md` line 42 calls `AtlasTOP/` "our domain layer on top of TagKit", and line 51 tells an implementer to "record the temporary workaround in `AtlasTOP/` (our layer)". Both contradict Decree 0002 §6 and Code-Style's structure-discipline rule, which names AtlasTOP as the example of what not to build.
- `Documenta/Agora/Dialogs/0024-top-as-a-paradigm.md` open question 2 asks which is current law.

A stale copy of QST-0018 also sat in `Curia/Questae/Open/` beside the Solved one.

## 🧾 Evidence

- `grep -rn AtlasTOP --include='*.py' .` outside the vault: only `AtlasTOP/archetypes.py` itself.
- `AtlasTOP/archetypes.py:7`: `from ._helpers import build_identity_tag`; `ls AtlasTOP` shows no `_helpers.py`.
- Julio, 2026-09-06: "AtlasTOP was explicitly forbidden. We should directly use the latest TagKit."

## 🎯 Desired outcome

`AtlasTOP/` is gone from the tree; no document describes it as a live layer; the Dialog 0024 question is answered by Decree 0002. Composition helpers live in the Kit that owns the axis (GuildKit, SpeciesKit, BackgroundKit), never in a catch-all TOP folder.
