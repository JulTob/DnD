## 🔍 Diagnosis (what & where)

Three deploy files disagree and none is current: `app.yaml` (App Engine, runtime `python314`, unverified), `Run_And_Deploy.sh` (Flask era: an `adventurer` venv, `FLASK_ENV`, Cloud Run from source with no Procfile), `app/Dockerfile` (gunicorn on `app:app`, Python 3.11, `--no-deps`). `requirements.txt` pins nine packages nothing imports. The footer's build stamp shells out to `git rev-parse`, which prints "build unknown" inside an image without `.git`.

## 🎯 Desired outcome

One target, one file, one command. Recommended: Cloud Run from a root `Dockerfile` (`python:3.14-slim`, `pip install -r requirements.txt`, `shiny run --host 0.0.0.0 --port $PORT app.main:app`), a `.dockerignore` that keeps `.recovery-vault/`, `Documenta/`, `docs/`, `Avatar/`, the SVG maps and `.git` out of the image, `requirements.txt` trimmed to `shiny` (pinned), TagKit and Pillow, the build SHA passed as `BUILD_SHA` at build time, and `app.yaml`, `Run_And_Deploy.sh`, `app/Dockerfile` deleted. Gate: build the image locally and run the smoke inside it.

- The decision is the target. App Engine is the alternative if `python314` exists there; then `app.yaml` stays and the other two go.
- Deploying is outward-facing: the first deploy is on Julio's word, from the main checkout, with the URL opened from a phone.
