## 🔍 Diagnosis (what & where)

Recovered ActorLudi `Map_of_Races.Player_Species(character)` draws `character.Pick(list(player), weights=player.values())`. There is no module global `player`. The same NameError is in live `AtlasAlusoris/Map_of_Races.py` (`random.choices(list(player.keys()), ...)`).

`AS_racial_modifier` in both trees calls `AS_background_modifier(npc)` and neither file defines or imports it.

This is recovered behaviour, not a restore mistake. RaceKit / generation do not call `Player_Species` today; `AS_racial_modifier` is reached from `apply_creature_ability_modifiers` (still imported from live `AtlasAlusoris`, see QST-0081.5).

## 🧾 Evidence

Vault `Player_Species` bytecode: `LOAD_GLOBAL player` twice. After `exec` of the pyc, `hasattr(mod, "player")` is False. `player` is not in the module's `co_names` as a stored global.

Live file has no `player =` assignment.

`AS_background_modifier` appears only as a call inside `AS_racial_modifier` (live and vault). `grep` of the repo finds no definition.

## 🎯 Desired outcome

Julio names the playable-species weight table (likely a subset of `race_weights`, or SpeciesKit `Playable_Species`) and either defines `AS_background_modifier` or deletes the call. Do not invent the dict.

## 🧭 Notes for the Agora / implementer

Do not silently alias `player = race_weights`. Player species and NonPlayer race weights are different questions. SpeciesKit already has `Playable_Species` / `NonPlayer_Species` as Pin Fields.
