## 🔍 Diagnosis (what & where)

Julio raised a performance and memory concern: the webapp may generate the same
character more than once during level-up or rebuild flows, and title lists may
be expensive if rebuilt repeatedly. The current code also mixes return and
yield shapes.

## 🧾 Evidence

- `Descriptor`, `Rank`, `Place`, `Artifact`, and `Origin` build candidate
  lists at call time.
- `Element(lusor)` shuffles a list and yields indefinitely.
- `Origin(lusor)` treats `Element(lusor)` as a value, not as an iterator.
- Webapp flows can revisit the same character seed when rebuilding or leveling.

## 🎯 Desired outcome

- The public title API has one clear shape.
- Memory behavior is intentional and simple.
- Repeated calls for the same character do not become needlessly expensive.
- Any cache or lazy behavior is justified by actual cost or a clear repeated
  work pattern.

## 🧭 Notes for the Agora / implementer

- Dialog 0007 should compare:
  - returning one title string per call;
  - yielding candidate streams internally;
  - immutable module-level word pools plus per-call selection;
  - seed/title memoization if repeated webapp calls prove costly.
- Keep user-facing title generation as a string unless Julio explicitly chooses
  a stream API.
- Add tests that reject generator-object text in final titles.
