## 🔍 Diagnosis (what & where)

Vault `AtlasEpica/Map_of_Scenes.py` (and restored `Charts_of_Scene_Binder`) treat the framing Character as `adventure.dm_character`. Live `AtlasEpica/Grimoire_of_Adventure.py` still stores `adventure.bbeg` and documents “BBEG Oracle”. There is no `dm_character` on Adventure.

After `Forge_Oracle`, the Target is a TagKit composition (`Adventure__Cave__Forest`). `adventure.dm_character` raises `AttributeError: ... has no Tag view 'dm_character'` instead of falling through to instance data. `adventure.bbeg` is the live field.

Scenes/Binder prose is the later morally-open “DM Character” wording. Grimoire still says BBEG.

## 🧾 Evidence

Vault `frame_briefing` bytecode: `LOAD_ATTR dm_character`. Live Grimoire `__init__` sets `adventure.bbeg = None`; `grep dm_character` in that file is empty. Restored `Map_of_Scenes.__main__` dies on `frame_briefing` after a successful `Forge_Oracle`.

## 🎯 Desired outcome

Julio either aliases `dm_character` on Adventure (and Collapse_Frame), or Scenes/Binder read `bbeg`. Do not silently map the names in one file only.

## 🧭 Notes for the Agora / implementer

Restored Map_of_Scenes keeps vault `dm_character` so the bytecode still tells the truth. Companion UI (`Charts_of_Scene_Binder.bind_dm_character`) already aliases `bind_bbeg = bind_dm_character` at the binder, not on the Adventure Target.
