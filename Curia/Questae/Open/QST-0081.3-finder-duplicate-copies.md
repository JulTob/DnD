## 🔍 Diagnosis (what & where)

The tree holds a large set of files named `* 2.py` and `* 2.md` next to the real modules (Finder-style duplicates). They are not on the import graph. During SpeciesKit restore they sat beside the vault shims and the recovered source, which makes `ls` and agent glob searches lie about how many copies exist.

## 🧾 Evidence

A `find` from repo root (excluding `.recovery-vault` and `.git`) counted on the order of two hundred ` 2.py` / ` 2.md` paths on 2026-08-31. Examples: `AtlasActorLudi/SpeciesKit/kinship 2.py`, `Curia/Questae/Working/QST-0081-restore-guilds-species-backgrounds-from-vault 2.md`.

Python will not import `foo 2.py` as `foo`. They are dead weight and a recovery hazard: an agent can edit the duplicate and think the live module moved.

## 🎯 Desired outcome

Julio decides whether to delete the Finder copies, gitignore a pattern, or move them out of the repo. After that, one path per module.

## 🧭 Notes for the Agora / implementer

Do not delete on a recovery agent's say-so if Julio still wants them as a backup. Do not merge them into the live files: the live files are the recovered source. QST-0052 already wants `$S/` and vault paths ignored; this is the sibling problem for Finder duplicates inside Atlas trees.
