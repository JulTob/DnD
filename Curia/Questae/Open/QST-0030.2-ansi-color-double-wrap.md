## 🔍 Diagnosis (what & where)
`_bug_report(exc)` (`Minion.py:223`) already colors each of its own sections individually — magenta header, dim timestamp, cyan call-stack, green bug-tree (`Minion.py:225-229`, each via `Color(text, "...")`). But `minion()`/`warden()`/`guardian()` then hand that *already-colored* string to `print_record(_bug_report(exc), FAIL_COLOR)`. When no Chronicler is open, `print_record` falls through to `_emit(text, color)`, which wraps the whole (already-ANSI-coded) string in `Color(text, FAIL_COLOR)` a second time (`Minion.py:48-51`). Under a Chronicler, the same double-wrap happens later, in `_read_account_aloud`'s `_emit(error_text, FAIL_COLOR)` (`Minion.py:119`). ANSI escape codes don't nest — the outer color code and the inner sections' reset codes collide.

## 🧾 Evidence
Captured directly from the live crash repro (see QST-0030.1's evidence) and from `python Minion.py`'s own self-test:
```
\033[93m\033[95m🧟 Minion bug report\033[0m
```
— yellow (`FAIL_COLOR`) immediately followed by magenta (the header's own color), followed by a reset that lands mid-report rather than at the end. Further down, a bare reset sits alone on its own line (`┷\033[0m`). The net effect: instead of a single, cleanly-colored block, the terminal shows a report where only fragments are colored as intended and the rest reverts to default color partway through — on every single failure, not an edge case.

## 🎯 Desired outcome
One color scheme applied once per report: either the outer `FAIL_COLOR` wrap, or `_bug_report`'s own per-section coloring — not both. The report should render as one coherent, fully-colored block with the reset landing only at the very end.

## 🧭 Notes for the Agora / implementer
- Two candidate fixes, either is small and mechanical (no Dialog needed, per Council below):
  1. Have `_bug_report()` return **uncolored** text and let the caller's single `Color(..., FAIL_COLOR)` wrap apply once, dropping the per-section colors — simplest, but loses the section-by-section color distinction (header/stack/bugs) that seems intentional.
  2. Keep `_bug_report()`'s per-section coloring, and have `_emit`/`print_record` **skip** the outer `Color()` wrap when the text already contains an ANSI escape (e.g. check for `\033[` before wrapping) — preserves the richer coloring, one extra guard.
- Whichever is chosen, re-run both the `Minion.py` self-test (`python Minion.py`) and a live crash repro to confirm the report renders as one clean block with a single trailing reset.
