## 🔍 Diagnosis (what & where)
`Minion.py`'s `@minion`/`@warden`/`@guardian` decorators each do, on failure: `print_record(_bug_report(exc), FAIL_COLOR); raise`. When a decorated function calls another decorated function (the normal shape of this codebase — `AtlasLusoris/Grimoire_of_Characters.py` alone has ~35 `@minion`/`@warden`/`@guardian` sites nested inside one another: `__init__` → `set_char_features` → `apply_species_features` → …), the same exception is caught and reported **again at every decorated frame it passes through**, each time with a longer, re-nested call tree that re-includes everything the previous report already showed.

Under `@chronicler`, this isn't deduped either: `print_record` special-cases `FAIL_COLOR` by appending straight to `_account.errors` (`Minion.py:101`) with no identity check, unlike the `seen` dict used for successful records (which does collapse repeats into `×N`). Every nested report reaches the closing section as its own separate block.

## 🧾 Evidence
Reproduced live (not just the `__main__` self-test) by calling `Character(char_class='Rogue', level=3, seed=3)` directly. One root cause — `TypeError: 'NoneType' object is not callable` inside `apply_species_features` (`Grimoire_of_Characters.py:181`, calling into a `None` species-feature callable) — produced **three full bug reports** in a single call, each one a superset of the last:

```
Report 1: 4 stack levels, ends at apply_species_features → __init__.py:64 __call__
Report 2: 7 stack levels — re-embeds ALL of report 1, wrapped in one more layer
          (Grimoire_of_Characters.py:63 __init__ → Minion.py:245 wrapped → set_char_features)
Report 3: 9 stack levels — re-embeds ALL of report 2, wrapped in yet another layer
          (<string>:7 attempt → Minion.py:245 wrapped → __init__ ...)
```
Same `type(exc).__name__`, same message, same innermost frame — three times, growing. In a call chain deeper than this minimal repro (real character/NPC generation nests further), this compounds further per additional decorated frame.

## 🎯 Desired outcome
One root-cause exception → one bug report, however many `@minion`-family frames it passes through on the way up. The report should still carry the *deepest/most complete* call tree available (don't lose information — just stop repeating it).

## 🧭 Notes for the Agora / implementer
- Two directions worth weighing in a Dialog, not picked unilaterally here:
  1. **Mark-and-skip:** stamp the exception object itself on first report (e.g. `exc._minion_reported = True`) so outer wrappers see it's already been reported and only re-raise.
  2. **Dedupe by identity at the Chronicler:** give `_account.errors` the same `seen`-style identity check the success path already has, keyed on the *innermost* frame + exception type/message rather than the full (growing) tree text.
- Option 1 fixes both the `@chronicler`-open and `@chronicler`-closed (immediate print) cases in one place; option 2 only helps when a Chronicler is open. Worth surfacing that tradeoff in the Dialog.
- Don't lose the outermost call-site context entirely — whichever approach wins, the single surviving report should still be the most useful one (likely the *last* one raised, since it has the fullest tree), not necessarily the first.
