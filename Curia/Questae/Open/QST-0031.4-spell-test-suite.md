## 🔍 Diagnosis (what & where)
There is no test suite anywhere in this repository — `scripts/test_character_url.py` is the one ad-hoc script that exists, and there's no `pytest` config (`pytest.ini`/`pyproject.toml`/`setup.cfg`) at all. The spell-system redesign (QST-0031.1–.3) is a large, mechanical, easy-to-silently-break migration — exactly the kind of change that should not land without automated verification.

## 🎯 Desired outcome
A real `pytest` suite (with minimal config added at the repo root) covering, at minimum:
- Every spell name appearing in a class/subclass list resolves to exactly **one** registry entry (the QST-0031.3 dedupe tripwire).
- Every `Spell` in the registry has a non-empty `definition`.
- Every Tag applied to a `Spell` actually validates against its `Expectation` (i.e. nothing non-Spell ever gets a spell Tag).
- `Spell.__format__` (QST-0031.5) round-trips for at least `html` and `md` specs without raising.

## 🧭 Notes for the Agora / implementer
- This is genuinely the first test suite in the project — the Artificer's seat (workshop/tooling) should weigh in on where config lives and what the minimal `pytest` setup looks like, since there's no existing convention to follow.
- Land this **alongside** QST-0031.2/.3 (write tests as the migration happens), not strictly after — a migration this size wants a safety net while it's still in motion, not just a checkmark once it's "done".
