# QST-0030.3 — `get_call_tree()` is silently empty for anything that isn't `app.py`/`shiny_app.py`

## 🔍 Diagnosis (what & where)
`get_call_tree()` (`Minion.py:158`) only starts building its tree once it sees a frame whose filename is in `_START_FILES = {"app.py", "shiny_app.py"}` (`Minion.py:9`). Any invocation that never passes through one of those two exact files — a standalone script, a REPL session, a pytest run, a notebook — never flips `active = True`, so the "Call Stack" section of every bug report is permanently empty (`\n╞🔮 Call Stack:\n├`) for that entire run, with no indication *why* it's empty.

## 🧾 Evidence
Reproduced by calling `Character(...)` directly from a one-off script (not through `shiny_app.py`) to chase the QST-0029 crash pattern — the exact kind of ad-hoc investigation QST-0029's own evidence section describes ("surfaced incidentally during a 100-seed sweep"). Every bug report in that run showed:
```
╞🔮 Call Stack:
├
```
with nothing between the two lines, regardless of how deep the actual call chain was — only `bugged_tree()` (the real traceback) carried any path information. The "Call Stack" feature silently contributes nothing outside the web app.

## 🎯 Desired outcome
Investigation scripts, tests, and notebooks get the same call-stack context the web app gets — or, if that's not desired, the empty section should say *why* it's empty rather than rendering as a blank, unexplained heading.

## 🧭 Notes for the Agora / implementer
- Simplest fix: when no frame in the stack matches `_START_FILES`, fall back to treating the *outermost* application frame as the start (i.e. `active = True` from the first frame that isn't Python/site-packages internals), instead of requiring an exact filename match.
- Alternative: make `_START_FILES` configurable (mirroring `set_log_file`'s pattern) so a test harness or script can declare its own entry point once, at the top.
- Reads as mechanical — shouldn't need a Dialog — but flag to the Agora in case there's a reason the two-file gate was deliberate (e.g. avoiding noise from internal Minion-to-Minion calls) that isn't visible from the code alone.
