## 🔍 Diagnosis (what & where)

`AtlasActorLudi/Grimoire_of_Skills.py`, `Char_Skills.activate_expertise` (~line 730):

```python
def activate_expertise(self, n, skill_names):
    # Randomly pick a skill from the list
    s = random.choice(skill_names)      # <-- the draw

    if n>0 and skill_names:             # <-- the guard, one line too late
```

The guard for "nothing left to pick" **exists** and is correct. It simply sits one line *below* the draw it is supposed to protect. The method recurses, removing a name from `skill_names` each time; when the list empties while `n > 0`, the next call reaches `random.choice([])` before the guard can stop it.

This is the same shape of defect as the one QST-0050 just fixed in the Feat pools: an empty pool treated as impossible rather than as an ordinary outcome.

## 🧾 Evidence

23 of 39 failures in a 180-Character sweep across all Guilds and levels 1/4/8/12/16/20 — roughly **13% of every Character generated**, and the single largest cause. First seen: Ranger, level 4, seed 7021.

```

  .../python3.14/random.py:353 in choice
```

Line 732 is the draw; line 875 is one of the recursive tail calls.

## 🎯 Desired outcome

A Character entitled to more Expertise than there are eligible Skills gets Expertise in the Skills that *are* eligible, and generation continues. Running out is a normal outcome, not a crash.

## 🧭 Notes for the Agora / implementer

*Proposals, not decisions — the Canon asks tickets to diagnose. Offered because Julio asked for the shape of the fix.*

- **Smallest safe fix (recommended for the recovery):** move the draw inside the guard, so the base case is reached before anything is drawn.
  ```python
  def activate_expertise(self, n, skill_names):
      if n <= 0 or not skill_names:
          return
      s = random.choice(skill_names)
  ```
  One reorder, no behaviour change on the paths that already worked, and it closes the crash for every Guild at once.
- **Check the sibling.** `activate_proficiencies` directly above shares the same recursive remove-and-recurse shape; confirm whether it has the same ordering and fix both together if so.
- **Proper fix, later, not now.** This is legacy pre-ledger code (long `elif` chain, mutating the caller's list, setting `proficiency_level` by hand). The lasting answer is to route Expertise through `ProficiencyKit`'s typed ledger the way `FeaturesKit._Plan_Training` now does, where a short pool is an explicit, named outcome (`allow_short`) rather than an accident. That belongs to the QST-0047 arc; **do not attempt it as part of crisis recovery** — restore correctness first, redesign after the tree is green.
- **Verify with:** the 180-Character sweep in the parent questa's evidence, plus `python -m AtlasLusoris.FeaturesKit` (its bulk test counts total generations).
