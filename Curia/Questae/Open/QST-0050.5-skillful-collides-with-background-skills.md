# QST-0050.5 — 🟡 Skillful spends its pick on a Skill the Background then grants anyway

- **Type:** bug (ordering) — *the second half needs a design decision*
- **Priority:** 🟡 normal — *no crash; a Human silently loses a Skill they are entitled to*
- **Status:** Open
- **Owner:** unclaimed
- **Route to:** Architecture Consul, Technical-Team, Julio
- **Parent:** QST-0050
- **Sidequests:** —
- **Related:** QST-0050 (the same collision class, solved for Tools) · `FeaturesKit.Reserved_Background_Training`

## 🔍 Diagnosis (what & where)

Human's `Skillful` Trait grants one Skill. Its Background then grants two more, from a **fixed** pair written into the Background. Nothing stops those overlapping, and when they do the Character is simply one Skill short of what the sheet promises.

This is the same defect QST-0050 fixed for Tools, but the Tool answer does not transfer. There, the Background chose its Tool from a menu and ran *last*, so `BackgroundKit._still_open` could pick around the Feat. Here the order is reversed and the Background's Skills are not a choice:

```
Grimoire_of_Characters.New_Player:
    Apply_Species(...)      <-- Skillful draws here; no Background exists yet
    Apply_Guild(...)
    Apply_Specialization(...)
    Apply_Background(...)   <-- the two fixed Skills land here
```

`Skilled` avoids this because its Imprint receives `background_tag` and passes `exclude=Reserved_Background_Training(background_tag)`. `Skillful.awaken` takes only `(char, first_gain)` — it has no Background to consult, because at that point in `New_Player` one has not been chosen.

## 🧾 Evidence

200 Humans (`species="Human", guild="Fighter", level=5`), every one of them receiving a Skillful grant:

```
Humans with a Skillful grant: 200   collisions with Background Skills: 23   (11.5%)
   ('Tomb Raider', ['Investigation'], background Skills ['Investigation', 'Religion'])
```

Roughly **one Human in nine** loses their species Skill to the overlap. It is silent: the ledger records the grant, the sheet shows the proficiency once, and nothing reports that a pick was spent twice.

## 🎯 Desired outcome

A Human ends up with their Background's two Skills **plus** a distinct third from Skillful. No crash today, so this is about the Character being whole, not about stability.

## 🧭 Notes for the Agora / implementer

*Proposals, not decisions — this one genuinely needs a Dialog before anybody edits.*

Three shapes, in increasing order of blast radius:

1. **Re-resolve Skillful after the Background.** Leave the draw where it is, and have the Background's Skill grant nudge a colliding Skillful pick to a fresh Skill. Smallest change; keeps generation order untouched. Costs: Skillful's Entry has to be re-projected (`Resolve_Skillful` already exists and rewrites that description, so there is a hook), and the Dice Bag draw for the replacement needs its own purpose so it cannot perturb the original stream.
2. **Choose the Background earlier**, before `Apply_Species`, so Skillful can `exclude=Reserved_Background_Training(...)` exactly as Skilled does. Conceptually the cleanest and makes the two Traits consistent. Costs: it reorders `New_Player`, which changes what **every** Character draws. Not a recovery-window change.
3. **Let the Background pick around the species**, mirroring the Tool fix. Costs: a Background's two Skills are *authored identity*, not a menu — an Artisan is Investigation and Persuasion. Swapping one because a Human got there first would make the Background lie about itself. **Recommend against**, noted only so the option is on the record as considered.

Leaning: **(1)** for now, **(2)** as the honest fix once the tree is green and a reorder can be verified against a full regeneration.

- **Do not** simply widen Skillful's pool or make it prefer rare Skills; that hides the overlap rather than resolving it.
- **Verify with:** the 200-Human probe above, expecting 0 collisions, plus a check that non-Human Species are unaffected.
