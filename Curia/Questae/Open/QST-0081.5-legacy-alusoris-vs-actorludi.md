## 🔍 Diagnosis (what & where)

There are two Alusoris trees. They share race *catalogues* (weights and subrace tables match field-for-field) and they do **not** share APIs. Recovery restored `AtlasActorLudi/AtlasAlusoris/` from vault `.pyc`. Live `AtlasAlusoris/` is still the old NPC-class / `app.random` world. Do not overwrite one with the other.

## 🧾 Evidence

Live **`AtlasAlusoris/`** (old NPC class world):

- `Map_of_NPC.generate_npcs(selected_race, selected_archetype, count)` → `NPC.NPC(race=, archetype=, lvl=10)` with `app.random`
- `Map_of_Archetypes.Archetype()` = `random.choice`; `AC_Archetype_modifier` uses **`"Guard"`**; **`AS_Archetype_modifier` mutates `npc.AS` with Dice**
- `Grimoire_of_NPC` is a **class NPC** with `__init__`, not a Character awakener
- Race pickers take no Character; they call `app.random.choices`
- `Humans` / `Elves` / `Halflings` / `Dwarfs` / `Lizardfolks` / `Snakefolks` / `Vampires` return `f"{chosen_type} "` (trailing space)
- No `Creature_Type_For_Race` / `CREATURE_TYPE_BY_RACE`

Recovered **`AtlasActorLudi/AtlasAlusoris/`** (vault):

- `generate_npcs(..., selected_background=..., seed=, level=10)` → `summon_nonplayer_list`
- `Classify_Archetype` routes exact names to Guild or Background; unknown raises
- AC table key **`Guardian`**; `AS_Archetype_modifier` is a no-op that returns `npc`
- `NPC(...)` is a **function**: interim constructor; `awaken_nonplayer` applies the Alusoris `NonPlayer` Tag then `Finish_Awakening`
- Race pickers take `character` and draw through `character.Pick`; `Humans(..., *, dice=None)`
- Subrace strings have **no** trailing space
- `Creature_Type_For_Race` maps Vampire → Undead, etc.

Wiring still pointed at the live package:

- `AtlasActorLudi/Grimoire_of_AbilityScores.apply_creature_ability_modifiers` imports `AtlasAlusoris.Map_of_Races.AS_racial_modifier` (global `Dice`), not the recovered ActorLudi function (`npc.Roll`)
- Recovered `Finish_Awakening` still calls `AbilityScores(..., character=npc)` — that is QST-0050.4, and it currently blocks `summon_nonplayer`
- Recovered `Finish_Awakening` / `set_stats` still call `SavingThrows(npc, npc.AS, pb)` and `Char_Skills(npc, npc.AS, pb)` — three positional arguments against today's two-argument kits
- Recovered `SetName` is `return npc.Naming(npc)` (bytecode: method plus an extra `npc`)
