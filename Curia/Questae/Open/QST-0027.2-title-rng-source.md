## 🔍 Diagnosis (what & where)

`Map_of_Titles` currently controls randomness by reseeding the module-global
random state. That conflicts with Decree 0002, which says every Character owns
its own Dice and every generation mechanism must roll through that source.

## 🧾 Evidence

- `Title(lusor)` calls `random.seed(lusor.seed)`.
- Selection helpers call global `random.choice` / `random.choices`.
- PC and NPC call sites also reseed global random before requesting a title.
- Existing Curia field notes already record that mixed RNG sources break seed
  reproducibility.

## 🎯 Desired outcome

- Title generation receives or obtains one explicit random source per call.
- The same lusor and same seed produce the same title.
- Generating one title does not perturb any other generator path.
- The public contract is clear enough for later integration with
  `Character.Roll(D=...)` / Dice.

## 🧭 Notes for the Agora / implementer

- Dialog 0007 should choose between:
  - passing an `rng` argument through `Title`, `Descriptor`, `Rank`, `Origin`;
  - adapting the Character Dice method;
  - a small module-level configuration hook for legacy callers.
- Julio approved a transitional `set_random(Dice)` interface: it sets the
  module's random source to the provided Dice, and falls back to Python's
  `random` when unset or `None`. The `Dice` parameter name is intentional: it
  keeps the code aligned with the project's model language and Decree 0002.
- Do not keep global seeding in the title map after this lands.
- Add deterministic self-tests with seeded random sources.
