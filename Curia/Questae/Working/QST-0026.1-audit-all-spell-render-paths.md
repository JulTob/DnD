## 🔍 Diagnosis (what & where)
Spell text is boxed because **upstream generators embed spell HTML inside `npc-textbox` divs**, and the Shiny sheet faithfully renders that HTML inside prose sections. The defect is not isolated to one cantrip (`Friends`) — it is a systemic pattern across feature and spellcaster string builders.

### Root cause for `Friends` cantrip (confirmed)

**Magic Initiate** feat (`AtlasLusoris/Grimoire_of_Features/__init__.py`, `MagicInitiate()` ~L1449–1461):

```python
bullets = "".join(f"<div class='npc-textbox'>{s}</div>" for s in chosen_cantrips)
# ...
_feat.description = (... + bullets + ...)
```

When `chosen_cantrips` includes `Friends`, `str(Friends)` expands to full spell HTML (`Lodge_of_Spells.Spell.__str__`, ~L1803–1821: name, cantrip label, definition). That entire block is wrapped in `npc-textbox` and injected into the **Features** section.

**User-visible symptom:** `Friends` + cantrip header + definition appear inside a bordered box under Features (e.g. "Magic Initiate (Bard)").

### Still present 2026-07-31 — Path A confirmed live (Julio: "the light cantrip shows html tags in the text")

Path A above is still unfixed and now shows raw tags, not just boxing. Aasimar
**Light Bearer** renders on the character sheet as:

> …The light can be colored as you like. `<br>` Covering the object with something
> opaque blocks the light.

- Author side: the description is code-authored HTML — `<b>`, a
  `<div class="spell">{Light}</div>` wrapper (`Grimoire_of_Features/__init__.py:937`),
  and the embedded spell text carries a literal `<br>` (`Lodge_of_Spells.py:290`).
- Render side: `feature_item` passes it to `ui.markdown()`
  (`app/components/shared.py:257`) — the **prose** door, which escapes markup.

This is the QST-0012 doctrine of three doors being violated: a *code-authored HTML*
string is going through the *markdown* door instead of `html_prose`. Any feature whose
description contains markup leaks tags; Light Bearer is only the most visible instance.

Same class of bug was fixed in the equipment rows on 2026-07-30 (`_equipment_rows` was
wrapping `Entry` HTML in `ui.tags.b(safe_str(...))`, which escaped it; changed to
`ui.HTML`) — so the pattern recurs wherever a Scriba object meets a markdown renderer.

## 🧭 Notes for QST-0026.2 (implementation)

**Do not patch only `Friends`.** Fix the contract at the source:

1. **Stop wrapping spells in `npc-textbox`** in `Grimoire_of_Spellcasters.py` and `Grimoire_of_Features/__init__.py` (and Training files).
2. **Emit spell prose** via `Spell.describe()` / markdown-friendly text, or a shared `spell_to_prose(spell)` helper in AtlasMagia or AtlasVenustas.
3. **Expand `spellbook_prose()`** in `shiny_app.py` to include full definitions for the Spells section (currently names-only).
4. **Features section:** spell grants (Magic Initiate, species cantrips, invocations) should reference spells in prose, not embed boxed HTML.

**Presentation layer (`shiny_app.py`) is not the primary bug** — it correctly renders markdown prose; the poison is in the HTML baked into `feature.description` and spellcaster `__str__` output.
