## 🔍 Diagnosis (what & where)

Julio: *"Probably we should separate the Proficiency and Tools/Kits to a separate module,
and weapons, and armor, and other items… Am I right or too worried?"*

He is right, and Canon says so twice:

- `Modus-Operandi` — "One purpose per unit. Small Maps, Kits, and components compose."
- `TagKit-Doctrine` — "Independent axes… must not be collapsed."

Two boundaries were actually wrong, and one was already fine:

1. **`Grimoire_of_Items.py` was misnamed.** `Conventions.md`: a Grimoire "coordinates a
   rite… not permission to accumulate unrelated behavior", while a **Kit** is "the
   preferred home for a stable domain object and its related Tags." That file is exactly
   a domain object (`Item`) plus its whole Tag family. It was never a rite.
2. **`Ledger_of_Gear` held three axes** — proficiency kits, survival gear, and bundles.
   A tool is what a *proficiency* looks like (ability score, evocative use), not a
   variety of rope.
3. **`GearKit` held the proficiency route** — "who may use what" is a different question
   from "what does this Character end up with." It is also not a Tag family of its own:
   it ROUTES between GuildKit's training Tags and ItemKit's gear Tags, which
   `Conventions.md` calls a `Map_of_X`.

Weapons / Armors / Wonders were **already** correctly separated as Ledgers — splitting
further would have been the "too worried" version.

## 🧾 Evidence

`Conventions.md` naming table: `Map_of_X` = "data plus the route or algorithm that
resolves a task"; `XKit` = "one domain object or Tag family and its public contracts";
`Ledger_of_X` = "ordered records, history, or enumeration".

## 🎯 Desired outcome

Each module answers one question, and its name says which.

## ✅ Resolution

- **Decided by:** Julio (asked the question; Canon supplied the answer).
- **What changed:**
  - `Grimoire_of_Items.py` → **`ItemKit.py`** (all 8 importers repointed).
  - Tools extracted to **`Ledger_of_Tools.py`** (25 kits, ability + inspiration);
    `Ledger_of_Gear` now holds only adventuring gear and the 7 packs.
  - Proficiency extracted to **`Map_of_Gear_Proficiency.py`**
    (`armour_allowance`, `weapon_pool`, `may_use_shield`, `unarmoured_formula`,
    `has_unarmoured_defence`), re-exported from `GearKit` so existing callers are
    unaffected.
  - `GearKit` keeps only loadout POLICY.
  - Each new module carries its own `__main__` self-test.
- **Practice/preference to remember:** when unsure whether to split, read the
  `Conventions.md` naming table — the right name usually decides the boundary. And a
  file whose name does not fit any row is the one that needs splitting.
- **Moved to Solved:** 2026-08-01
